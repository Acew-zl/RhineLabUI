# 顶部书脊与打开方式（0.4.0）

2026-09-16。用户明确要求书签 Logo/备注位于空间中朝上的顶部窄面。最终贴图沿 X 方向排布，表面法线为 +Y，位置 y=3.702；宽 4.32、厚度方向 0.27，保持原模型和镜头。竖直侧面不放书签信息，正面恢复原来的莱茵标签和编号。

## 实现

- 顶部标签复用一个实例化纹理图集，选中档案独立纹理为 2048×128。Logo 与名称仍有独立开关，沿用已有偏好键。正面与顶部纹理独立，关闭两项不隐藏正面标签。
- 切档归位副本各自复制正面和顶部纹理，避免快速切档时旧档案变成新书签。标签跟随卡片矩阵、升降及归位；360° 拆解时顶部标签属于 carrier 框架，正面标签属于 cover。
- 新增 OPEN LINKS：默认 new-tab，当前页为显式选项；书签主入口、详情按钮及页脚、搜索匹配、搜索提交都调用同一打开函数。新页使用 noopener/noreferrer，不改变导航页地址或选档状态，不增加权限。
- 针对首字占位，图标读取改为浏览器本地接口响应 → Blob → ImageBitmap → Canvas。依次尝试页面 32px、16px、站点首页；失败可手动重试，设置显示数量或失败原因。每个请求有超时，最多六个并发，无第三方图标请求。

## 验证

- 34 项回归通过：书签映射、循环、原内容与动作、预热、顶部几何范围和 +Y 法线、新标签页默认/当前页选择、可执行 URL 拦截、图标读取及解码失败后的回退。
- `npm run build:extension`、`npm run check:extension`、`npm run build` 通过；扩展权限未变。构建仅有已有的大代码块提示。
- Chrome 本地实际产物 + 同样 CSP + 明确标注的演示书签：确认最终标签位于顶部朝上的窄面，正面恢复原始外观；检查明暗主题、独立查看器载入/拆解、显示开关、返回及切档。
- 新标签页测试使用本地目标 URL：点击搜索后出现独立目标标签，原导航标签 ID 和 URL 保持；切换 current-tab、刷新后仍保存，提交本地 URL 则改变原页地址。测试结束恢复 new-tab。
- 图标回退用故障注入测试验证（首次读取失败、第二次解码失败、第三次成功）。HTTP 预览无真实 favicon API，画面中的首字明确是占位，没有把它当作真实站点 Logo 验收成功。

真实安装扩展中的站点图标问题尚未直接复现；既有浏览器安全限制仍阻止自动化访问扩展页面。新版提供读取状态，若用户仍见首字，需要结合安装环境及该状态进一步定位。实现参照 [Chrome 官方 favicon 接口说明](https://developer.chrome.com/docs/extensions/how-to/ui/favicons)。
