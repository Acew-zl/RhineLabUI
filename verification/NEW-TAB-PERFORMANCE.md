# 起始页 GPU 占用与帧率控制 · 0.8.4

日期：2026-09-28。用户反馈打开起始页后 Windows 任务管理器 GPU 3D 占用达到 99%。本次新增帧率控制，未移植上游功能或改变模型、镜头、文字纹理、分辨率和光影配置。

## 原因与范围

原实现使用每次 `requestAnimationFrame` 更新场景，随屏幕刷新率运行。空闲档案起伏持续改变实例矩阵，无法命中静止画面复用。完整质量的折射、阴影、AO 及独立清晰书脊层仍需绘制；高分辨率增加每帧成本。预加载只把首次编译提前，不能减少进入阵列后的持续负载。

本机物理显示器为 2560×1600、165Hz，包含集成 AMD Graphics 与 RX 6800S。测试 WebGL renderer 确认为 RX 6800S 的 ANGLE/D3D11，未使用软件渲染。不限帧测试实际只有约 44 FPS，说明它已经受渲染负载限制；不能声称实际达到了 165 FPS。

任务管理器的 3D 数值是对应 GPU 引擎的忙碌比例，显卡总览采用最忙引擎，而不是显存使用量或全部引擎的平均值。参考 [Microsoft 官方说明](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/)。本次没有把系统其他程序的总占用误算为起始页占用。

## 实现

设置 → 画面与性能 → 动画帧率：

| 模式 | 操作/开场帧率上限 | 空闲上限 |
| --- | --- | --- |
| 均衡（默认） | 60 FPS | 30 FPS |
| 节能 | 30 FPS | 15 FPS |
| 跟随屏幕刷新率 | 不额外限制 | 不额外限制 |

- 输入结束约 4 秒后降低频率；长拖动、惯性与程序选档保留操作频率。输入唤醒只在从空闲进入操作时重置门控，持续鼠标移动不会绕过帧率限制。
- 跳过帧不会推进虚构时间，也不会追补一串重绘；动画继续接收真实时间。隐藏标签页沿用原有停止三维更新的逻辑。
- 主场景和独立书脊层一起限帧；两层保持屏幕分辨率。帧率偏好即时保存，旧偏好默认迁移为均衡；画质与减少动态效果设置保留。
- 普通网页也可使用帧率选项；Wallpaper Engine 仍遵循宿主帧率设置，不叠加本限制。

## 实际显卡对照

使用已构建扩展资源、相同 CSP、公开演示书签。Edge 154.0.4258.37 的隔离无头浏览器，CSS 视口 2048×1280、DPR 1.25，对应两个 2560×1600 原生画布。静置 7 秒后测量绘制次数，每档读取 8 次 WDDM GPU Engine 样本；通过浏览器 CDP 获取该测试实例的 GPU 进程 ID，仅采集其有效 3D 计数。

| 模式 | 空闲实际重绘/秒 | 测试浏览器 GPU 3D 均值 | 连续鼠标移动重绘/秒 |
| --- | --- | --- | --- |
| 跟随屏幕（原行为） | 43.52 | 88.26% | 44.33 |
| 均衡 | 30.08 | 61.75% | 47.44 |
| 节能 | 15.10 | 48.57% | 30.03 |

均衡较原行为下降约 26.5 个百分点，节能下降约 39.7 个百分点。GPU 频率、电源策略、其他程序和设备会影响占用；本结果不是对所有用户的占用保证，也不代表功耗同比下降。开场、操作及首次着色器编译仍可能出现较高负载。无头浏览器结果不能替代真实 165Hz 前台窗口测试；高刷门控另以 60/120/144/165/240Hz 时间序列验证。

详细原始数据：[results.json](newtab-performance/results.json)。对照图：[原行为](newtab-performance/display.png)、[均衡](newtab-performance/balanced.png)、[节能](newtab-performance/efficient.png)。GPU 对照完成后仅调整版本号及选择框样式；最终 Chrome 0.8.4 再做了 UI 回归，[最终设置截图](newtab-performance-chrome/settings.png)、[Chrome 回归数据](newtab-performance-chrome/results.json)。

## 验证

- 网页、完整版、Chrome 商店版构建成功，TypeScript 检查通过。
- 完整版 23 项检查通过，包含高刷限帧、连续输入、恢复与旧偏好迁移；Chrome 默认搜索 3 项检查通过。两包本地资源、CSP、权限、版本及搜索提供者边界检查通过。
- 实际浏览器连续移动鼠标未突破设置上限；左右切列正常；通过真实「档案详情」按钮进入特写并返回；帧率设置可操作，重新加载后仍保存。两次完整运行与最终 Chrome 包回归均无 JavaScript 异常。
- 两层画布尺寸一致，截图检查书脊与界面清晰度；此项未用真实个人书签测试 favicon，也未替用户修改已安装扩展。
- WDDM 通配计数器可能含已退出的其他进程；采样脚本仅保留当前测试 GPU 进程且 Status 为 0 的样本，数据不足时失败，不用无效样本填零。

复现需要 Node.js 24 与 Playwright（可通过 `PLAYWRIGHT_MODULE` 指定模块路径）：先 `npm run build:extension`，再 `node scripts/check-newtab-performance.mjs`。Windows 设置 `GPU_COUNTERS=1` 可同时采样 WDDM；`PERFORMANCE_ROOT`、`PERFORMANCE_OUTPUT` 与 `PACE_CASES` 可选择构建、输出目录和模式。此脚本不依赖真实用户书签，不作为商店安装验证的替代。
