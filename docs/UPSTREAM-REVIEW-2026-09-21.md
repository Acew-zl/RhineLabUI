## 精细动效控制

来源：[PR #9](https://github.com/LBEILC/RhineLabUI/pull/9)，合并提交 `3f4b9c9`。原 PR 介绍写 15 项，后续删除无效的平滑滚动选项；最终 [motion-preferences.ts](https://github.com/LBEILC/RhineLabUI/blob/6185da2b1891aa9484e90ef233d360cdae655b89/src/motion-preferences.ts) 是 **14 项**。

由原先统一的“减少动态效果”，扩展为完整、减少及分项自定义。精细项目按五组折叠，除了开场下次重播生效，其余设置即时应用并保存。首次无偏好时跟随系统，已有分项优先，其次兼容旧总开关。

| 分组 | 最终独立开关 | 对当前起始页的价值判断 |
| --- | --- | --- |
| 开场 | 开机动画 | 当前已有完整、简短、直接进入三种启动方式，单独再增加开关会重叠，需要统一规则 |
| 档案阵列 | 选档波浪、静止起伏、指针视差、拖动惯性、切档/切列过渡 | 波浪、起伏与视差可按个人舒适度选择；若只想减少晃动，仍能保留选档动画 |
| 档案详情 | 抽取/归位与详情镜头、模型解密、正文揭示 | 可以保留模型仪式感，同时让正文直接出现；正文揭示开关较适合实用书签页面 |
| 界面 | 文字滚动、数字滚动、窗口过渡 | 文字滚动可独立关闭，切换后更快读到书签名；数字与弹窗仍可保持动画 |
| 360° 查看器 | 旋转/平移/缩放阻尼、模型拆解/重组/清晰度过渡 | 有益但属于低频入口，优先级低于阵列与文字 |

这里是独立控制现有动画，不是新增模型或重新设计整套动效；关闭动画也不等于提高渲染分辨率。它不是针对我们此前清晰度问题的专项修复。

### 同批修复

最终源码和[上游验证记录](https://github.com/LBEILC/RhineLabUI/blob/6185da2b1891aa9484e90ef233d360cdae655b89/verification/MOTION-INTEGRATION.md)还包含：

- 模型解密关闭时，详情直接清晰；回阵列和归位副本恢复磨砂。正文揭示可独立运行。
- 详情、弹窗、页签与查看器进出正确服从窗口过渡开关；中途关闭动画时结束对应状态，并处理焦点和旧回调。
- 精细动效设置适配暗色文字、分隔线、选中态与焦点提示。
- 删除没有实际效果的 `smoothScroll` 偏好；读取旧设置时忽略此字段。
- 扩展分项保存、旧偏好迁移与交互检查脚本。上游记录了 Chrome / Edge 和模拟壁纸宿主测试；本次没有自行运行上游程序，不能把上游测试当作本扩展兼容性验证。

这些修复主要服务于新的分项控制。当前扩展尚没有这套状态，因此不能仅凭标题就认定当前版本存在同样缺陷、需要立刻套用补丁。

### 采用建议（待用户决定）

**值得优先考虑**：文字滚动、静止起伏、指针视差、选档波浪、正文揭示的独立开关。它们能兼顾导航实用性与原有动效，尤其是只关闭文字滚动、保留三维动画这一组合。

**可以暂缓**：拖动惯性、选档轨道、抽取镜头和 360° 查看器的更多分项。当前交互已经成熟，增加设置也增加理解与验证成本。

**不建议直接整包合并**：上游同时修改 `src/main.ts`、`src/scene.ts`、`src/model-viewer.ts` 和多处 CSS；这些位置与我们的启动预热、三种启动模式、书脊独立渲染、选中高度、镜头、清晰画质、书签映射及设置分组有交集。若后续采用，需要保留扩展逻辑，并单独核对旧偏好迁移、快速切档/归位、启动模式与各动效组合。上游壁纸工作台和 HUD 的开关映射没有必要加入扩展设置。
